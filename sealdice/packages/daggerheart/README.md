# 匕首之心 sealpack · 0.2.1

从零实现的正式版核心Dice扩展：.dd/.ddr、当前人物卡动态资源和频道GM恐惧池。静态角色资料与升级由PbDH负责。**本版未接入.pbcha导入、Chat人物卡、实时标签或完整术语库**；旧zzz车卡器不作为集成来源。

## 掷骰

```text
.set dh
.dd +3 dc15 -- 攀爬
.dd 敏捷 adv2 dis1 [15] -- 越过断桥
.ddr 本能 +2 dc14 -- 避开落石
```

二元骰固定d12。普通优劣势按来源抵消后至多投一枚d6，关键成功优先于难度；没有难度不编造成功/失败。原因写在独立的 -- 后；未知参数拒绝。仅@骰子可用，拒绝代骰/援助，不扣其他玩家资源。

## 动态资源

**无需Chat人物卡，也无需.dh init。** 原生.st可直接设置属性、资源和上限；这就是普通.dd插件的使用入口。后续Chat人物卡按钮仍写这份Dice属性，不切换另一份状态。静态角色最终来自PbDH，但未接入时.st照常可用。

```text
.st 敏捷2 生命上限6 压力上限6 护甲上限2 生命0 压力0 护甲0 希望2 金币0
.dh status
.dh 希望 -1
.dh hp +1
.dh 压力 =0
.dh 金币 +5
```

同一份Dice当前人物卡属性与.st共用；Chat的缓存不是另一份资源数据库。生命、压力、护甲为已标记槽，希望为可用点数（上限6）。金币为整数计数，不自动换算单位；PbDH系统字段及单位映射将在导入阶段确定。手工增减越界拒绝，自动希望/恐惧获得按上限封顶。

模板明确默认生命/压力/护甲/金币0、希望2、护甲上限0，六属性0；.st会省略与默认相同的值，插件按当前daggerheart-native模板读取，生命与压力上限不设默认。

资源不完整或未指定GM时.dd照常投骰并提示手动.st结算，不把缺失资源当0。资源完整且频道GM已指定时自动结算；反应有完整资源即可处理经历成本。关键成功获得1希望并清除1压力；反应不产生这些变化。已有上限变得小于当前标记数时拒绝写入，须先明确处理冲突，不静默截断。

## GM恐惧池

```text
.dh gm claim
.dh gm set SEALCHAT:某个用户ID
.dh fear
.dh fear +1
.dh fear =0
```

首次指定须群管理及以上；当前GM或群管理可交接/解除（.dh gm clear），恐惧池保留。只有当前GM或骰主可手动改恐惧，上限12。按平台完整频道ID隔离并持久化，不依附玩家卡；私聊不能管理池。

## 经历与速查

.dh experience只读列出导入经历；.dd 敏捷 exp:e1 dc15使用稳定经历ID，先验证余额，每项消耗1希望，然后在一次操作中结算结果。当前PbDH导入尚未发布，因此普通玩家暂用数字修正进行掷骰，必要费用用.st手动处理；不接受旧expN自报经历。内部DH经历是[{"id":"e1","name":"经历名","value":2}]字符串，保留给未来导入器；本扩展不提供静态编辑器。

.dh rule 核心提供简短核心结算说明；完整检索与PbDH术语映射仍待后续Issue。

## 错误、重复消息与恢复

验证参数、余额和权限先于投骰。适配器有稳定rawId时，同频道同用户最近100次操作重复消息复用原结果；无rawId无法保证网络重发去重，不承诺自动识别不同消息中的重复点击。

动态写回前将意图及原骰值写入扩展持久存储，失败后冻结该频道后续写操作。原操作人切回同一角色执行.dh recover；仅当前字段与原前值/目标值兼容才完成原操作，不重新投骰。遇到外部变更冲突拒绝覆盖，需维护者核对备份。

Dice属性与扩展存储不是同一数据库事务；.st或character.set等外部并发写入不受此日志锁保护。不能宣称跨库原子性、任意重发幂等或Chat并发已验收。核心属性通常按60秒周期落盘；突然结束进程可能丢失未落盘属性，即使扩展回执已存在。恢复日志处理的是检测到的写回失败，不能保证进程崩溃前全部结算已持久化；重启验收会等待宿主保存周期。备份应保留人物属性数据库和本扩展存储；卸载不自动清除人物资源字段。

## 安装与开发

用SealDice1.6.1及以上扩展包管理上传本.sealpack，安装、启用并重载模板/脚本后.set dh；停用旧.dd同名扩展。只有纯JS和V2 YAML模板，无网络、HTTP、文件读写权限，无Node运行时依赖。基础包原真实1.6.1验收已通过；本版本验收结果见仓库开发文档。

本地npm test和npm run build；tools/native-smoke.py提供官方1.6.1的隔离验收，不连接IM账号或生产。GitHub Release提供包与校验和，不等于服务器已部署。PbDH/Chat集成按公开Issues继续推进。
