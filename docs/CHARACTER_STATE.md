# iframe人物数据与恢复

## 数据职责

PbDH当前Character Save保存完整人物、资源与账号云同步关系。Dice保存当前频道/账号绑定人物卡的资源副本、闪避与阈值以及DH来源/DH姓名确认标记。六特质、经历、装备由iframe生成数值公式，不自动写入Dice。

其他聊天平台可主动导入PbDH的.st数字快照，再用特质名掷骰；经历手动加到修正，hope/hopeN指明本次费用。不同平台/账号/频道的人物卡不自动共用数据。旧HTML人物卡与Dice经历协议已废弃。

## 关联与同步

首次关联明确以PbDH资源初始化Dice，中文JSON校验白名单、UUID、姓名和范围后通过官方seal.vars/Goja玩家上下文写入；来源标记最后写，iframe回读全部数值与姓名才确认。昵称不等于人物卡管理器的卡片元数据。

重连要求DH来源/DH姓名与当前存档一致、SDK权限有效及资源合法，只回读Dice当前资源。升级旧DHPbDH标记到本版后需重新关联一次。资源与徽标后续只同步变化字段；徽标字段以PbDH为准，资源回读沿用Runtime、本地自动保存和云outbox。

采用官方context.read、characters.read、characterCard.read、messages.send。SDK没有原子expectedCardId/版本条件写入；发送前读卡只能缩小误绑窗口，不能保证外部切卡并发原子性。

## 掷骰写入与消息去重

费用、骰面、回复、每个字段的操作前后值、原玩家/人物卡标识和GM状态先保存为pending，然后写希望/压力/GM恐惧，完成后保存receipt并清除pending。稳定rawId与玩家ID组成请求键；最近100条完成消息返回原回复，不重投或再支付。没有稳定rawId时不能保证重复投递去重。

pending按群保存；私聊按玩家保存。有未完成操作会阻止后续掷骰/GM修改和关联初始化，避免后一次覆盖恢复意图。

## dh recover

用于补完未完成操作，不撤销已完成掷骰、不重新产生骰面，不重新扣第二份费用。原玩家必须回到同一群或私聊并使用原人物卡；涉及GM时也检查其原人物卡标识。

对每个字段先检查：当前值是before或after才允许。before会补写after，after保持同一最终值；两者都不是时拒绝覆盖，提示联系骰主处理冲突。全部检查通过后才补写，最后记录原消息回执并返回原回复附（已恢复）。

例如希望3，花费2后得到希望结果，同时关键成功清压力1：最终希望2、压力从2到1。如果希望2已写，压力写入失败，recover只完成压力1，返回同一次骰面。若期间希望被外部.st改为0，recover拒绝，不擅自猜测新的正确余额。

恢复机制不接管原生.st、.dh pbdh初始化或PbDH云存档；不提供跨库事务，不锁外部写入，不替代备份。宿主属性约60秒保存，突然杀进程可能让意图/字段丢失或不一致，不能承诺任何崩溃下都自动恢复。卸载不主动删资源。
