# 匕首之心人物卡数据与通信方案

默认使用SealChat原生人物卡HTML及Dice插件接口。固定Chat 7a7b5bb / Dice 1.6.1，只读核对接口，不修改、打补丁或重编译宿主。

## 数据归属

| 内容 | 保存与通信 |
| --- | --- |
| 六特质、资源和上限、闪避、阈值、金币把/袋/箱、GM恐惧 | Dice原生人物卡；宿主下发attrs，手动操作.st，掷骰.dd/.ddr；恐惧不出现在HTML |
| 经历名称与修正 | PbDH编辑；“导出为海豹骰”的同一条.st写入Dice绑定卡DH经历，HTML回读并提供勾选 |
| 角色名、头像 | 使用Chat/Dice现有功能，宿主下发name/avatarUrl |

用户已将资料范围收敛为经历；种族、社群、职业、等级、装备、职业特性、卡牌、物品与笔记不导入、不展示。图片不解码、不上传、不进Dice属性。人物卡使用同一通用HTML，不生成角色专属模板，不存localStorage或Embed共享Storage。

DH经历为schemaVersion=1的JSON字符串，仅experiences数组，每项name/modifier。最多5项、名称1–60字且单行、整数修正-20至20；读入字符串不超过4096字符。PbDH导出替换经历列表并按原有流程录入数值；人物卡不把窗口缓存数值回传。普通.st show通过自有指令的展示白名单隐藏字段；.st export仍可能包含它，.st clr会清空它。

## 原生通信与扣费

宿主SEALCHAT_UPDATE下发windowId、name、attrs、avatarUrl；HTML通过SEALCHAT_EVENT/ROLL_DICE的template模式发送完整命令。相对资源操作发.st 希望-1等；PbDH导出一条.st，包含原有数值赋值及DH经历的双重JSON字符串引用。全角符号先作Unicode转义，避免原生.st的符号规范化改写名称；空列表覆盖旧经历。人物卡无文件导入入口。

掷骰窗勾选经历，发送例如.dd 敏捷 exp=1,2@内容版本。经历名称不进入算式，修正与希望在Dice执行时从当前卡读取。内容版本变化、选择不存在、希望缺失/不足或算式无效时，在投骰前拒绝。数字额外修正仍不自动扣希望；明确勾选的每项经历消耗1希望，零修正也支付，反应掷骰同样支付。

费用先从当前希望扣除，再应用该次希望收益/压力效果；例如希望6用1经历且希望结果，最终仍为6。费用写回纳入已有意图日志、角色/字段校验及最近100条稳定rawId去重；失败.dh recover恢复原次结果，不另发.st扣费。存在待恢复资源操作时，自有.dh exp写入仍被拒绝；原生.st按宿主现有规则执行。

不调用UPDATE_ATTRS、characterCard.updateAttrs或character.set。宿主现有UPDATE_ATTRS会合并窗口缓存并整卡提交，即使只改变资料字段也可能覆盖刚发生的.st；本方案使用原生.st和插件资源结算避开该路径。

## 接口与持久化边界

- 原生请求走普通聊天，无静默或执行回执；以Dice回复为准，超时不自动重发。
- 宿主约10秒回读当前活动卡，HTML等待回读后展示保存经历，不以草稿冒充成功。Dice属性约60秒周期落盘，突然退出可能丢失未保存修改。
- 指令发往当前频道/聊天身份绑定卡，窗口展示卡未必相同。原生协议无原子expectedCardId校验；内容版本仅检测经历变更，不是卡身份/权限保证。
- 稳定rawId去重及恢复意图不等于与外部.st/character.set的事务、严格并发或跨设备去重。
- 已有巨型base64旧卡仍可能被宿主加载；PbDH海豹骰导出不写任何图片，不自动迁移旧库。

可选频道Embed使用相同经历字段与掷骰命令，需要context.read、characters.read、characterCard.read、messages.send，以当前用户/活动卡为准。伴随context/connection事件由刷新队列合并，不依赖Storage或attachments权限。

## 验收

插件及人物卡测试通过。固定Chat实际注入代码的HTML测试覆盖LF/CRLF与脚本转义。浏览器协议模拟覆盖多经历选择、费用提示、希望不足、零值和重开；文件导入已移除。

隔离官方未修改Dice1.6.1覆盖Unicode/引号单字段导入、常规.st show隐藏、当前数值计算、多项/零修正扣费、余额不足与失效选择、无效算式不扣费、包重载、外部.st及保存周期后的进程重启。最近验收报告保留在忽略的runtime/acceptance-0.4.7，测试数据库、日志与可执行副本可清理。完整未修改Chat/Dice真实联动尚未完成，生产未部署。

## 3D骰子

插件输出海豹注解：希望N[1d12]+恐惧N[1d12]，优劣势追加实际N[1d6]。只读提取固定SealChat的annotDice3DBotPattern验证全部144种二元结果、动作/反应与优劣势；开启3D的宿主可从机器人回复生成动画。实际部署Chat的完整联动仍待复验。DiceVisualPayload只有整次appearance，groups仅type/results，无法通过现有二次开发接口给两颗d12分别着色；未修改宿主。

## 数值展示

自有.st指令扩展只接管daggerheart模式的show/list，使用21个有用数值字段的白名单，只展示已录入整数并保留0；按字段名/别名选择与整数阈值筛选仍可用，其他.st录入/增减/导出等返回未处理，由原生指令执行。DH经历、DH角色标识及任意附加字段不显示；内部角色标识仍用于恢复核对，不删除，不修改存储。角色数据导出仍可包含内部字段，显示白名单不是权限边界。

HTML移除槽位方块和其他已有属性区，四项资源每卡单行显示标签、数值/上限、减/加；金币区标题下固定三卡同排，金币把/金币袋/金币箱使用10/10/1固定上限。零值可操作，减到0或加到上限时停用对应按钮；缺失金币可点数字明确录入，读取不自动补0或把旧单字段金币换算为单位。PbDH海豹骰导出分别提取handful-gold/bag-gold/chest-gold当前数量；仅UI采用用户要求的固定上限，不改变PbDH本身的规则或自动兑换。
